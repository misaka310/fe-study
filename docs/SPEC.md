# 基本情報技術者 合格ナビ — Product Specification

## 1. 元の目的

ITパスポート相当の知識を持つ学習者が、基本情報技術者試験（FE）の科目A・科目Bを、用語の意味、判断軸、問題文の条件、誤答理由まで説明できる状態へ進める日本語学習サイトを提供する。

教材設計では、学習パス、概念比較、図解復習、用語説明、全選択肢の排除理由を一貫して扱い、学習者が「なぜその答えになるか」を追えることを品質基準とする。

## 1.1 ポータル構造の正本

全画面共通のサイトヘッダーと目的ナビ、トップの学習パス・問題演習・図解一覧、教材の章一覧＋本文という構造を正本とする。教材画像は章の先頭へ固定せず、関連する節の途中へインラインで埋め込む。

## 2. 期待する最終結果

- 全画面共通のポータル構造で、「教材」「問題演習」「弱点補強」「模試」「学習記録」へ移動できる。
- 12章の教材を、各章の要点、判断軸、混同しやすい概念、関連問題へ接続して読める。
- `TTL` などの略語・専門語をクリックまたはキーボードフォーカスして、正式名称、意味、試験での判断ポイント、混同注意を確認できる。
- 説明図を、装飾ではなく「要素・矢印・比較軸・ラベル」で理解できる教材資産として、関連節の途中へ表示する。
- 問題演習では、固定順の暗記だけに依存しないよう、問題プールを分野・難易度・出題型で分散し、同一概念を複数形式で出題する。
- 独自作成問題を合計215問以上収録し、現行統合版では265問（科目A 165問・科目B 100問）を収録する。
- ユーザー提供の追加教材から、既存問題と過度に重複しない問題だけを選別して統合し、採用問題は総合解説と4択それぞれの具体的な採否理由を保持する。
- すべての問題で、正答、問題文の決め手、総合解説、4選択肢それぞれの採否理由、関連教材を表示する。
- 科目A 60問 / 90分、科目B 20問 / 100分の模試、回答保存、再開、採点を維持する。
- 全問、科目別、分野別、未回答、誤答、弱点補強、模試の各モードを利用できる。
- 通常問題の演習画面で、全科目（265問）、科目A（165問）、科目B（100問）を切り替え、未回答・誤答・弱点補強の条件を選んでも科目分類を維持できる。絞り込み時は対象件数と元の母数を併記する。
- 回答履歴、正答率、弱点ランキング、分野別成績、累積誤答、JSONバックアップ／復元をブラウザ内だけで維持する。
- IPAのシラバスVer.9.2、試験要綱、2023〜2026年度公開問題への公式リンクをまとめる。公開問題本文は転載しない。
- 検証済みソースをGitリポジトリへ保存し、構成済みのホスティング環境へ所有者限定で同じソース状態をデプロイする。
- READMEから目的、主要機能、ローカル起動手順、プライバシー、開発文書へ迷わず到達できる。

### 完成扱いにしないもの

- 抽象的なコンピュータ画像だけを表示し、本文の概念を説明していない図。
- 略語を展開せず、専門語を知っている前提で読み進めさせる本文。
- 問題文や選択肢を覚えた順番だけで解ける固定リスト。
- 正解だけを示し、誤答選択肢を外す理由がない解説。
- 同一テンプレートの数値や名詞だけを変えた水増し問題。
- テスト、build、lintだけ成功していて、ローカル実ブラウザで教材・用語チップ・問題・模試を確認していない状態。
- GitHubとSitesで異なる未統合ソースを「完成」として扱う状態。

## 4. ユーザー操作・導線

### 問題演習の基本要件

- 合計215問以上とし、科目Aは165問以上、科目Bは50問以上を最低条件とする。現行の目標は265問（科目A165問・科目B100問）とする。
- 科目Aは四肢択一を基本とし、計算、用語理解、設計判断を偏りなく含める。
- 科目Bは擬似言語読解、配列、探索、整列、スタック・キュー、再帰、計算量、プログラム修正、情報セキュリティ事例を含める。
- 模試は問題バンクから科目・分野配分を保って抽出し、再作成できる。
- 合否表示は公式のIRT得点を偽装せず、正答率による学習上の目安であることを明記する。

### Happy Path

1. トップで「この順番で進める」または目的ナビから教材を開く。
2. 左の章一覧から章を選び、章の要約、判断軸、用語チップ、節途中の説明図、関連問題を確認する。
3. `この章の問題を解く` から問題へ移動する。
4. 問題文の条件を読んで回答すると、正解／不正解と次の問題への移動操作をすぐ確認できる。解説は回答直後から自動表示し、決め手と各選択肢の排除理由をその場で確認できる。
5. 関連教材または弱点復習へ戻り、学習記録で未解決トピックを確認する。

問題演習の左メニューでは、通常問題を「全科目」「科目A」「科目B」で分類できる。例えば「科目B」から「未回答だけ」へ移動しても科目Bの条件を保持し、「未回答だけ · 208問（全265問中）」のように現在の件数と母数を区別して表示する。基本問題20問×5セットは科目Aの知識問題として通常問題とは別に扱う。

教材内の章切替は、本文だけを差し替える場合でもURL履歴を章IDへ同期し、切替時はページ上部へ戻す。ブラウザの戻る／進むではURLに対応する章へ復元し、`?view=materials` のように章IDが省略された場合は先頭章へ戻す。

問題バンク件数など正本データから算出できる表示値は、画面コンポーネントへ固定値として重複記載せず、問題データから導出した値を利用する。

### 主要状態

- 読み込み中: 教材またはブラウザ内学習履歴の準備中であることを表示する。
- 通常: 現在の章・問題・模試状態と次の行動を表示する。
- 成功: 回答結果、正答理由、履歴反映、模試採点結果を表示する。
- 失敗: 該当問題なし、無効なバックアップ、画像読み込み失敗を利用者向けの日本語で表示し、別導線を案内する。
- 再開: ページ再読み込み後も模試の科目、問題順、現在位置、残り時間を復元する。

### エラー時

該当問題なし、無効なバックアップ、画像読み込み失敗、URL状態の不整合が発生した場合は、日本語で原因と復旧先を示し、利用者がトップ・教材・問題演習のいずれかへ戻れるようにする。

## 5. コンテンツ仕様

### 教材

各章は次の順で構成する。

1. まず理解すること
2. 判断軸（何を見て選ぶか）
3. 似た概念との違い
4. 試験でのひっかけ・注意点
5. 用語チップと説明図
6. この章の問題

本文は「用語の定義 → 役割 → 使う場面 → 使わない場面 → 関連する用語」の順で書く。略語は初出で正式名称を表示し、以降も用語チップから再確認できる。

### 用語チップ

用語データは教材本文から分離して検証可能にする。最低限、次を持つ。

```ts
type GlossaryEntry = {
  term: string;
  expansion?: string;
  meaning: string;
  examCue: string;
  contrast?: string;
  related?: string[];
};
```

本文中の明示マーカーからのみチップ化し、一般語を過剰にリンクしない。デスクトップではツールチップ、タッチ端末では同じ情報を閉じるボタン付きのポップオーバーとして表示する。`aria-describedby` または `aria-expanded` を付け、キーボードで操作できること。

### 問題

- 既存問題のID、正答、学習履歴互換性は維持する。
- 問題プールの出題順は固定にせず、セッション単位で決定論的にシャッフルする。
- 同じ概念を、定義問題、比較問題、条件適用問題、計算・追跡問題、誤り発見問題の複数形式で出す。
- 選択肢は正答以外も、なぜ条件に合わないかを一意に説明できるものにする。誤答は原則として正答と同じ論点・比較軸の中で迷える現実的な候補にし、画面設定・文字コード・ファイル名など設問の判断軸から明らかに外れた語を埋め草として使わない。
- 回答直後は正誤と前後移動を優先して表示し、「次へ」を解説や長いスクロールの後に置かない。解説は回答直後から自動表示し、「解説を見る」の追加操作を要求しない。「条件」「決め手」「正答の仕組み」「他の選択肢を外す理由」「関連教材」の順で表示する。
- 問題文・選択肢・解説にTCO、KPI、SLAなど学習上意味のある英字略語が現れる場合、解説内で英語の正式名称と短い日本語の意味を確認できるようにする。CPUなど十分に基本的な略語、単位、SQL予約語、変数名は過剰表示を避けるため対象外にできる。
- 問題データは独自作成とし、IPA公開問題の本文は転載しない。
- ユーザー提供の追加問題は既存問題との類似度を自動検査し、過度な重複や露骨な誤答ヒントを除外する。

## 6. ビジュアル仕様

- FEの学習概念を直接説明する図を使用する。
- DNSとTTL、TCP/UDPと通信層、サブネットとルーティング、認証・アクセス制御を含む教材図を、関連する章の節途中へ埋め込む。
- 各図は背景演出よりも、短い日本語ラベル、方向を示す矢印、比較軸、入力から結果までの流れを優先する。
- 生成後に実ファイルを目視確認し、文字の誤り・欠落・意味不明な表現がある図は再生成するか教材から除外し、装飾だけの図を無理に各章へ割り当てない。
- 図のメタデータには `id`、`src`、`alt`、`label`、`description`、関連章を持たせる。
- 標準問題と基本問題のうち331問にWebPの問題解説図を付与する。追加した科目B48問は本文解説を基本とし、変数追跡やデータ構造など図解効果の高い最大14問だけ画像を付与する。
- 問題解説図は現在の問題を解いている間に、次の問題の画像だけを先読みして、`次へ` 押下後の解説表示時の待ち時間を隠す。同じ画像URLへの先読み要求は共有する。
- 問題解説図のHTTPエラーや読み込み失敗は、問題回答フローを止めず日本語の代替メッセージへフォールバックする。

## 制約条件

- 他の資格教材や問題を出典不明のままFE向けコンテンツへ流用しない。
- Googleログインは任意とし、未ログイン時はローカル保存を維持する。ログイン時だけFirebaseの利用者別領域へ学習履歴を同期し、外部解析サービスは追加しない。
- 既存の問題演習、模試、学習履歴、JSONバックアップの主要URLと操作を削除しない。
- 説明図の生成手段やプロバイダは製品仕様へ固定せず、採用可否は最終画像の意味・正確性・可読性で判断する。
- フロントエンド依存関係を増やさず、既存のReact / Next互換構成を利用する。
- 構成済みホスティングの所有者限定公開を維持し、ユーザーの明示指示なしに公開範囲を広げない。
- 構成済みSitesは認証必須のため、通常の変更受入で外部ブラウザから本番サイトへログインして確認することを必須にしない。画面表示・導線・問題内容は、同じ統合HEADをローカル起動したブラウザで確認する。ホスティング側はデプロイ成功とGitの統合HEAD一致を別途確認する。

## 非目標

- 他の資格教材・問題の内容を、権利や出典を確認せずFE教材へ複製すること。
- Googleログインを必須にすること、未ログイン時のローカル動作を削除すること、外部解析サービスを新規導入すること。
- 既存の主要URLや学習フローを別方式へ置き換えること。

## 8. 受入条件

- [ ] 教材約12章が実内容を持ち、科目A・Bの必須分野と相互リンクをカバーする。
- [ ] 独自問題が合計265問、科目A 165問、科目B 100問存在する。
- [ ] 全問題に一意ID、科目、分野、論点、問題文、4件以上の選択肢、正答、総合解説、選択肢別理由がある。
- [ ] 問題文と選択肢の重複・過度な類似・露骨な誤答ヒントを自動検査できる。
- [ ] 全365問の英字略語を監査でき、TCOなど対象語は解説で英語の正式名称と短い意味を表示し、CPUなど対象外の基本語は不要な補足を表示しない。
- [ ] 科目A 60問・90分、科目B 20問・100分の模試を作成・再開・完了できる。
- [ ] 全問、科目別、分野別、未回答、誤答、弱点補強、模試が機能する。
- [ ] 問題演習で全科目・科目A・科目Bを選択でき、各分類の件数と絞り込み後の母数が正しく表示される。
- [ ] 回答履歴、累積誤答、分野別成績を保存し、JSON書き出し・復元・不正JSON拒否が機能する。
- [ ] 教材から関連問題、結果から関連教材、トップから主要機能へ迷わず移動できる。
- [ ] 教材内の章切替でURL・本文・スクロール位置が同期し、ブラウザの戻る／進むと`?view=materials`への復元が正しく機能する。
- [ ] 問題バンク件数のUI表示が問題データの件数から導出され、固定値の更新漏れが起きない。
- [ ] モバイル幅とデスクトップ幅で主要操作が利用でき、キーボードだけで解答・移動できる。
- [ ] 解説図対象331問のWebP画像が実ファイルと一対一で対応し、現在の問題を解いている間に次問画像を先読みして解説表示時に404や不要なlazy遅延を発生させない。
- [ ] READMEとサイトに非公式教材、公式採点非再現、公式資料リンクを明記する。
- [ ] `npm run lint`、`npm test`、`npm run typecheck`、`npm run build`、データ検証、主要ユーザー導線のE2Eが成功する。
- [ ] 検証済み統合HEADがGitの既定ブランチへpushされている。
- [ ] 同じ統合HEADから作成した成果物が構成済みホスティングへ所有者限定でデプロイされ、デプロイ状態が成功している。
- [ ] 同じ統合HEADをローカル起動した実ブラウザでHappy Pathを最初から最後まで通し、期待する最終結果を確認できる。
- [ ] 必須の異常系・復旧導線を確認できる。
- [ ] 「完成扱いにしないもの」に該当する状態を完成として報告していない。

## 9. 検証方法

```text
npm run lint
npm test
npm run typecheck
npm run build
npm run test:e2e
npm run verify:ai
```

ブラウザ検証は、認証付きSitesへ外部ブラウザでログインして行うのではなく、同じ統合HEADをローカル起動して行う。ローカルブラウザ検証ではコンソールエラー、4xx/5xx、画像404、キーボード操作不能、モバイルのレイアウト崩れを失敗として扱う。完了報告では、変更ファイル、実行済み検証、未確認項目、Git状態、Sitesデプロイ状態を明記する。
