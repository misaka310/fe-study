# FE Study Learning Experience Redesign

## Goal

基本情報技術者の教材サイトを、汎用イメージ中心のポータルから、SAAリポジトリの品質基準を取り入れた「判断軸・比較・図解・用語・問題解説」がつながる学習体験へ刷新する。

## Decisions

- 既存のURLクエリによる画面切替、問題ID、学習履歴スキーマ、模試仕様は維持する。
- UIはSAAの緑系をコピーせず、FE向けの暖色紙面＋濃紺インク＋オレンジの行動色で再設計する。
- 教材・問題・用語・図解メタデータを別データとして保ち、各データをテストできる構造にする。
- 本文は明示的な用語マーカーからだけチップ化する。
- 画像はima2で説明図を生成し、画像自体の視覚的な意味をブラウザで確認してから採用する。

## Architecture

`app/page.tsx` は既存のURLルーティングを維持し、各画面は既存コンポーネントを使い続ける。新しい `GlossaryTooltip` は教材本文の表示責務だけを担当し、問題・模試・学習履歴ロジックへ依存しない。教材の説明品質は `MaterialSection` の判断軸・比較・注意点フィールドで表現し、表示は `MaterialReader` 内の小さな表示コンポーネントへ分離する。図解は `src/content/visuals.ts` を唯一のメタデータ源とする。

問題の「覚えゲー化」対策は、学習履歴互換性を壊さずに出題順をセッション単位でシャッフルし、問題データの品質検査を拡張する。現行問題をすべて捨てるのではなく、再利用できる良問のIDを維持し、曖昧な問題や単純定義問題を改稿・追加する。

## Visual language

- 背景: 暖色の紙面、薄い罫線、濃紺の本文
- 行動色: オレンジ
- 情報色: 青緑
- 章カード: 章番号、学習目的、判断軸、進行矢印
- 図解カード: ラベル、見るポイント、関連章、拡大ボタン
- 説明ブロック: 「結論」「なぜ」「混同注意」の3段階

## Failure handling

- 用語データにないマーカーは通常のテキストとして表示し、ページを壊さない。
- 図解の読み込み失敗は alt と説明文を残し、他の教材を利用できる状態を維持する。
- 空の問題プールは既存の別モードへの復帰導線を表示する。
- シャッフルは問題IDとセッションシードから決定し、同じセッション中の再レンダーでは順番を変えない。

## Verification

ユニットテストで用語マーカー、用語データ、問題品質、シャッフルの決定性を確認する。Playwrightでトップ、教材、チップ、図解拡大、問題解説、弱点復習、模試再開、375px幅を確認する。ima2画像は各ファイルを目視し、説明内容とラベルの正確性を確認する。
